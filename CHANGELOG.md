# Changelog

Los cambios relevantes se registran aquí. La versión estable `v1.0.0` se etiquetó el 26/11/2026 en `main`.

## Unreleased

### Fixed

- Recuperación de contraseña y recordatorio de usuario en Render (DEF-042, MEVI-127, EV-2026-11-27-01): el plan gratuito de Render bloquea los puertos SMTP (25, 465 y 587) desde septiembre de 2025 y el servicio no tenía el correo configurado (respondía 503). Con `BREVO_API_KEY` el correo sale por la API HTTPS de Brevo, con el remitente de `SMTP_FROM`; sin esa variable se sigue usando SMTP. Si Brevo rechaza el envío, el enlace se borra. En local el envío por Gmail funcionaba, pero las cuentas tenían correos de ejemplo de otros buzones: ahora usan direcciones del buzón del proyecto (cambiables en «Mi perfil»). CP-118 en `auth.brevo.test.js`.
- Mensaje del 503 de la recuperación por correo (DEF-043, MEVI-132): decía «falta configurar SMTP», también en Render, donde el correo sale por Brevo. Ahora dice «falta configurar el correo (Brevo o SMTP)». CP-119 en `auth.correo-no-configurado.test.js`.

### Security

- Permisos de inventario terminado (DEF-044, MEVI-134, EV-2026-11-27-03): el supervisor podía registrar ingresos y salidas manuales de producto terminado y ver su historial llamando a la API, aunque el panel no le muestra la vista de Inventario (nunca lo hizo: todos los registros son del almacenista). Esas rutas (`POST /api/inventario`, `POST /api/inventario/{id}/salida` y `GET /api/inventario/movimientos` y `/{id}/movimientos`) ahora son solo del administrador y del almacenista; el supervisor sigue consultando las existencias y registrando el consumo de materia prima desde Seguimiento. CP-120 en `inventario.permisos.test.js` y matriz de permisos E2E.

### Documentation

## 1.0.0 - 2026-11-26

Primera versión estable: reúne todo lo desarrollado hasta el 26/11/2026 (PR #1 a #127), con las 25 historias y los 29 requisitos funcionales implementados. MEVIPLAST delegó en el equipo las decisiones pendientes y la aprobación del instructor sigue pendiente.

### Security

- Cerrar sesión revoca el token en el servidor (HU-020, RF-005): `POST /api/auth/logout` sube la versión de sesión del usuario (`usuarios.sesion_version`, migración `20261124_sesion_version.sql`) y los tokens anteriores responden 401; restablecer la contraseña también cierra las sesiones abiertas. Antes era una limitación aceptada (DEF-006).
- Resto de la auditoría de seguridad (run-1): cabeceras `X-Frame-Options: DENY`, `frame-ancestors 'none'` y `nosniff`, sin `x-powered-by`; el token de restablecimiento se comprueba antes de calcular bcrypt; las transacciones de inventario validan la línea con su propia conexión (no piden otra al pool); el supervisor ya no recibe el cliente de las ventas en el historial de inventario (CR-021) ni registra consumo en órdenes de otro supervisor; el login no deja la contraseña en el historial del navegador; el sanitizador quita U+FFFE y U+FFFF, que dañaban el Excel de ventas.
- Correcciones de la auditoría de seguridad (skill security-audit de Cloudflare, run-1): la recuperación de contraseña y el recordatorio de usuario solo responden a una coincidencia exacta del correo y envían el mensaje a la dirección guardada (antes, la collation sin tildes permitía que «ana@émpresa.com» recibiera el enlace de «ana@empresa.com»); el correo SMTP exige TLS (`requireTLS`) cuando `SMTP_SECURE` no es `true`, así que sin STARTTLS no se envían la clave ni el token; `db:init` siembra las cuentas DEMO solo en una base nueva o con `DB_DEMO=true` explícito, nunca al migrar una base existente.

### Security

- El servidor publica solo el build de React (DEF-028, observación del instructor). Antes Express servía toda la carpeta `frontend`, y desde el navegador se podían abrir `js/login.js`, el código fuente del panel (`/src/...`), `package.json`, `vite.config.js` y `node_modules`. El sitio público, el inicio de sesión y la recuperación de cuenta pasaron a React (`frontend/src/paginas`) y forman una sola aplicación con el panel; las imágenes pasaron a `frontend/public/assets`. Se conservan las direcciones `/`, `/login.html`, `/recuperar.html` (los enlaces de los correos siguen sirviendo) y `/dashboard.html`; cualquier otra responde 404. Una prueba de rutas verifica que esos archivos ya no se publican (EV-2026-11-16-01).

- El supervisor ya no ve ventas (CR-021): la API responde 403 a sus consultas de la lista de ventas, los comprobantes, el reporte de ventas y su Excel. En Reportes solo le aparecen producción y rendimiento de operarios, y su Inicio muestra las órdenes finalizadas en lugar del total vendido. Los precios, totales y clientes son información comercial del administrador; el supervisor sigue viendo las existencias para planear (EV-2026-11-11-02).

- Un administrador ya no puede quitarse su propio rol, desactivar su cuenta ni eliminarla, y el sistema nunca se queda sin un administrador activo: esos cambios responden 400. Antes la API lo permitía y el sistema podía quedar sin nadie que administre usuarios; en la tabla de usuarios, la fila propia muestra «Tu cuenta» en lugar de «Desactivar» (DEF-021, EV-2026-11-09-06).
- El supervisor ya no puede registrar ventas por la API (`POST /ventas` responde 403); sigue consultando ventas, comprobantes y reportes. Antes la API se lo permitía aunque su menú no tenía la vista Ventas (DEF-007, decisión del equipo con la delegación de MEVIPLAST).
- `npm audit` vuelve a 0 vulnerabilidades en backend y frontend (había 3 moderadas en herramientas de desarrollo, halladas en la instalación limpia del 2026-11-08): `vite` 6.4.4 → 6.4.5 y `minimatch` 10 → 11.0.5 dentro de `nodemon`, mediante un `override` porque `nodemon` 3.1.14 todavía pide la versión 10. Ninguna llegaba a producción (`npm audit --omit=dev` ya daba 0).
- Los formularios ya no usan atributos de validación en el HTML (`required`, `maxlength`, `minlength`, `min`, `max`, `step`, `type="email"`), por indicación del instructor. El panel valida con su propio código (campo obligatorio, largo, número positivo, correo) y muestra «Completa el campo …»; el servidor sigue validando todo y ahora rechaza con 400 los textos más largos que su columna (`validarLongitudes`, y medida, calibre y color de las variantes), en lugar de fallar al guardarlos.
- La API solo acepta llamadas de otros dominios listados en `CORS_ORIGINS`.
- El token de un usuario desactivado, eliminado o con el rol cambiado deja de servir de inmediato (401), en lugar de seguir vigente hasta 8 horas.
- Un token vencido o inválido responde 401 en lugar de 403, para que el panel cierre la sesión y lleve al login.
- `nodemailer` 7.0.13 → 10.2.1 y `body-parser` 1.20.8 → 1.20.9 (dependencia de Express): `npm audit` queda sin vulnerabilidades. El backend requiere Node.js 20 o superior.
